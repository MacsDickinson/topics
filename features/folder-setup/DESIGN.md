# Folder setup and topic review design

Status: implementation design, pending integration with accepted desktop design foundations and frozen service contracts. Use the existing system font, semantic surface/text/border/action tokens, controls and system light/dark mappings. Setup and review add patterns, not a competing theme.

## Screens and states

- **Connect and inventory:** selecting a new root starts local inventory only. Show a tree of folders with editable suggested roles and explanations, counts, date range, linked/unlinked counts and eligible bytes. Expand folders for individual sources. Clearly list exclusions including local-only material; roles never grant privacy permission. Empty folders offer adding notes and manual capture; returning roots open the map with resume/update available. Inventory loading, errors and root changes retain no stale root content.
- **Choose and consent:** tree controls select the proposed eligible folder without typed paths; optional dates narrow it. Preview the exact resolved manifest and exclusions, runtime and batch limits. One explicit authorization applies to that manifest only. Editing selection or stale bytes invalidates its consent; show a refreshed diff and retain completed unaffected work. Runtime unavailable leaves browsing and manual capture available.
- **Build:** progress announces processed, remaining, failed and excluded counts, with pause/resume and retry where supported. Browsable draft results remain visibly drafts; completion means all eligible selected sources were processed; failed and outstanding selected inputs remain gaps, and exclusions are listed separately without implying the whole folder was analysed. Restart restores checkpoints and edits.
- **Map and briefing:** a deterministic SVG graph and equivalent keyboard-operable list expose the same nodes, connections and evidence. Explicit connections use solid lines and text; inferred associations use dashed lines and text. Select a topic to read sourced statements grouped as a briefing. No summary supplies facts without underlying citations. Evidence is a native disclosure, closed by default, with full paths, dates and excerpts. Narrow layouts stack the graph/list and detail.
- **Save:** preview a service-issued exact receipt listing topics, statements, relationships, required endpoint dependencies and open issues. One Save starting map action approves only that receipt; group save uses the same dependency-aware service. Stale receipts require a fresh preview. Saved imports say From your notes, never Confirmed by you; untouched items remain drafts.
- **Review in context:** each enumerated visible section has Confirm, That's wrong, Add context and Not now. Confirmation names the exact count. Corrections show before/after, exact affected set and future rule before approval, referencing the actual user statement. Deferred issues remain open. Group repeated occurrences into one question with its evidence; incoming evidence shows a topic diff and does not overwrite accepted understanding.

Use semantic headings, native buttons and disclosures, visible focus, status announcements, and textual state labels in addition to color or line style. Respect reduced motion; keep long paths and evidence readable at narrow widths. Extend the integrated design-system documentation with these tree, receipt, graph/list and issue patterns in the same integration change.

## Evidence plan

Browser IPC fixtures demonstrate presentation and actions only: inventory/consent; progress and stale scope; graph/list and evidence; receipt and deferral; correction and exact confirmation; empty, runtime unavailable, narrow and dark states. Native isolated synthetic fixtures must exercise the actual service adapters, restart, one manifest authorization and one baseline save for 100 notes. The 21 approved scenarios map to service evidence in the owning core/job changes, with desktop evidence for the visible portions; browser fixtures are never proof of persistence or privacy enforcement. Record RED before implementation, GREEN commands and limitations, and synthetic light/dark/narrow/corrected-topic/graph screenshots after integration.
