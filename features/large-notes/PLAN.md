The separate approved window and setup exclusion work continues independently; reconcile against its final code before implementation. User approval of this plan and scenarios is required. Eventual substantive build also requires the user-requested Claude review.

## Outcome and boundary

Analyse every byte of an eligible, explicitly selected long Markdown source through bounded passages while preserving the original source and its provenance. The synthetic complaint is a 167.4 KiB note; this is not a measured performance result. Keep the existing graph, correction, privacy, proposal, approval and journal/undo machinery. A completed analysis means every required primary range was delivered and successfully committed, not that every fact was extracted or verified.

Proposed initial limits, for approval: an original UTF-8 document up to the existing 2 MiB source ceiling; primary chunks at most 32 KiB raw UTF-8, with at most 2 KiB preceding context inside the same selected source, and at most 128 chunks per source. The minimum 32 KiB is a ceiling, not a target: split earlier at Markdown heading/paragraph/line boundaries; split long lines at UTF-8 scalar boundaries. Never normalize, re-encode, or split a code point. Preserve all bytes (including CRLF, combining characters, fenced blocks and front matter); these boundaries are retrieval heuristics, not a full Markdown parser. Chunk plan partitions [0, length) into nonempty, contiguous, nonoverlapping primary ranges; overlap is a bounded prefix, never a second coverage unit. For an empty document use an explicit empty-source successful unit without a fabricated citation. Refuse non-UTF-8, over-2-MiB, over-128-unit, unrepresentable or budget-exhausted inputs with specific local explanation and actions to exclude or revise selection; never silently truncate. 2 MiB/32 KiB and boundary choices can exceed 128 chunks on pathological small sections: coalesce adjacent sections to the cap where possible; otherwise report the limit. Do not promise timing, extraction recall or cost.

## Exact consent, projection and evidence

Manifest preview locally computes a deterministic versioned chunk plan from the exact original file bytes and freezes source ID, local path, full document hash/length, primary and transmitted byte ranges, each range hash, algorithm version, budgets and batch identities into the fingerprint reviewed before consent. Preview shows selected files, per-file chunk count, selected bytes, exclusions, maximum attempts/calls and configured runtime; it does not pretend role/date hints establish truth. Chunk ranges are internal to that exact consent; newly discovered files or changed content/labels/root generation require a new preview and consent before affected transmission. Revalidate full hash, canonical path and privacy before each chunk read and again at guarded publication; a mid-run change blocks outstanding work and makes old evidence stale. Retain unaffected completed sources; for a changed source, invalidate its old chunk coverage, draft contributions and dependent context as needed, do not mix versions, and show what is retained. Any invalidation must preserve human edits and existing accepted records/history as stale or needing review, never silently delete them. Reconsent explicitly covers the new outstanding source version, preserves unaffected consent lineage and never implicitly admits new files.

Each run gets a fresh immutable capability for exactly one chunk (including its explicit overlap), no file-reading tool or other document access. Core/store reads and validates full local source but returns only the approved projection; enforce permitted byte ranges during candidate validation, including source endpoints and all draft/accepted context citations. Existing `SourceRef` already represents exact original-document byte ranges, full-document hash, passage hash, excerpt and optional heading: retain it for durable evidence; no synthetic chunk document or relative-offset citation. Host returns absolute original offsets with exact raw excerpt and SHA-256; any model subrange must lie within transmitted range, be on UTF-8 boundaries and match bytes/hash. `locator_valid` currently checks nearest preceding line beginning `#`, not a Markdown heading hierarchy: emit its actual matching heading or null, including heading-at-chunk-start and fenced `#` edge cases; do not invent heading paths. Validate all citations against the unchanged whole original. Protect TOCTOU at read and stage; malformed/out-of-range/forged headings or hashes fail closed. Do not return or permit fresh citations to out-of-window earlier chunks, even when they belong to the same source. Prior draft and accepted context may contain only eligible, privacy-filtered canonical identity/correction material whose disclosure does not expose out-of-window source excerpts or metadata; if required evidence cannot be safely represented, fail with an actionable context error. Do not infer permission from source-ID membership.

No public-context identity oracle: existing context retrieval must not disclose a topic, human correction, hidden name, source ID/path, heading, excerpt, parent filename or inferred identity because it matches an unselected/private document. Metadata is content: do not send a path/title/heading outside the selected projection or a generic filename hint unless independently authorized for this chunk. Prefer opaque run-local aliases on wire, resolve to canonical IDs/paths only in trusted host; the actual citation mapping must be host-validated, not model-supplied. This requires a wire mapping/protocol change, including rewriting validated citations and endpoints, not merely hiding a UI label. Associated eligible prior context must pass the same existing sensitivity, provenance and correction filters; suppress private/superseded human text and unselected cross-source evidence. Generic date/source-type hints may be omitted; if included they are selected-source retrieval hints only and cannot resolve identity, rank truth or create evidence. Scope delivery and source-bound assertions must test metadata as well as body.

## Accounting, budgets and lifecycle

Extend core-owned manifest/capability/checkpoint contract with source-version/chunk identities and coverage, while keeping source-level selected/processed/failed/outstanding reporting. Commit each successful chunk's buffered candidates, ID mapping and coverage atomically through the existing `CommitPermit` fence; mark a file processed only when all its primary chunks committed for the same hash. A failure, empty response without actual scope delivery, cancellation, exhausted attempt/candidate budget or restart mid-attempt leaves that chunk outstanding/failed; prior committed chunks and edits survive, no partial candidates escape. Retry only outstanding chunks within the consented finite attempts and total batches; explicit re-preview/reconsent if changed budgets are needed. Resume skips completed chunk IDs. Coverage UI shows files and chunks, gaps and exclusions, never claims full-folder coverage. A turn with 64 candidates may miss more: expose candidate saturation as an actionable gap, not complete; define safe retry/splitting under consent and finite limits before implementation. If exhausted, stop with a retry/new-preview action; do not call it analysed.

Keep the current 64 KiB aggregate raw batch budget and 512 KiB frame, 256 KiB host response, 64 runtime candidates, and 2 MiB output caps. Account actual JSON serialization including duplicate excerpt/content, schema, escaped text and both SDK/direct envelopes; raw source bytes are not wire bytes. Before publication, pack the mandatory source projection plus eligible accepted/correction context and schema; existing packer trims only optional draft context. Large accepted context alone can exceed the bound even with a tiny chunk. Do not trim corrections, suppress privacy filters, or retry forever: fail before transmission with an actionable context/budget error and permit a narrower approved selection or a separately designed bounded canonical context contract. Optional draft records remain whole and dependency-consistent, with explicit partial notice; omitted context is not negative evidence. Verify actual worst-case envelopes with synthetic escape-heavy, multibyte and large mandatory accepted/draft fixtures. No arithmetic claim that 32 KiB necessarily fits the wire.

Overlap never counts twice as coverage or independent corroboration. Canonical evidence identity includes source version and absolute byte range; merge overlapping/identical citations from the same document as one underlying source occurrence while preserving distinct supporting passages and source lineage. Different copies are not independent confirmation. Reuse existing ID mapping and precise human corrections across chunks; repeated facts remain one fact when supported by the same evidence, but ambiguous same-name people, conflicting assertions, changed values and distinct endpoints remain issues, not automatic merges. Deduplication cannot rely only on hashes of exact excerpts (overlapping ranges may differ). Re-runs and reconsent must not duplicate topics/claims or revive suppressed assertions; test negative cases to avoid overmerging.

## Alternatives and decisions requested

Raising 64 KiB alone still fails for larger notes, duplicates content on wire and retains full-file disclosure; disabling validators is unacceptable. Hard truncation loses coverage. Sending whole documents per chunk defeats isolation. A separate vector store or knowledge-store rewrite is unnecessary. The above smallest coherent slice supports one complete large file within the existing 2 MiB source ceiling and all lifecycle/security paths, not just happy-path splitting; ordinary files can retain their current path while shared contracts remain compatible. Decide whether to approve the 32 KiB/2 KiB/128 proposed limits, opaque alias protocol, handling of mandatory context overflow, and candidate saturation/retry semantics. These choices require validation through actual RED and wire-size measurements; do not treat this proposal as authorization.
