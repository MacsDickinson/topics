# Large Markdown notes: proposed plan for approval

Status: **discovery proposal, not approved or implemented**. Base `8dd17514d939914230d976bc01b019a0a1c82c15`. The separate approved window and setup exclusion work continues independently; reconcile against its final code before implementation. User approval of this plan and scenarios is required. Eventual substantive build also requires the user-requested Claude review.

## User summary

A selected long note would be analysed in small, overlapping passages under one reviewed plan. Progress would show the file complete after each required passage is delivered and staged; citations still point to unchanged original Markdown, and private or unselected material stays private. The proposal needs approval before any build.

## Outcome and boundary

Analyse every byte of an eligible, explicitly selected long Markdown source through bounded passages while preserving the original source and its provenance. The synthetic complaint is a 167.4 KiB note; this is not a measured performance result. Keep the existing graph, correction, privacy, proposal, approval and journal/undo machinery. A completed analysis means every required primary range was delivered and successfully committed, not that every fact was extracted or verified.

Proposed engineering limits: an original UTF-8 document up to the existing 2 MiB source ceiling; primary chunks initially at most 16 KiB raw UTF-8, with at most 2 KiB preceding context inside the same selected source, and at most 256 chunks per source. These are ceilings, not targets: split earlier at Markdown heading/paragraph/line boundaries; split long lines at UTF-8 scalar boundaries. Never normalize, re-encode, or split a code point. Preserve all bytes (including CRLF, combining characters, fenced blocks and front matter); these boundaries are retrieval heuristics, not a full Markdown parser. Chunk plan partitions [0, length) into nonempty, contiguous, nonoverlapping primary ranges; overlap is a bounded prefix, never a second coverage unit. For an empty document use an explicit empty-source successful unit without a fabricated citation. Refuse non-UTF-8, over-2-MiB, over-256-unit, unrepresentable or budget-exhausted inputs with specific local explanation and actions to exclude or revise selection; never silently truncate. 2 MiB/16 KiB and boundary choices can exceed 256 chunks on pathological small sections: coalesce adjacent sections to the cap where possible; otherwise report the limit. Do not promise timing, extraction recall or cost.

## Exact consent, projection and evidence

Manifest preview locally computes a deterministic versioned chunk plan from the exact original file bytes and freezes source ID, local path, full document hash/length, primary and transmitted byte ranges, each range hash, algorithm version, budgets and batch identities into the fingerprint reviewed before consent. Preview shows selected files, per-file chunk count, selected bytes, exclusions, maximum attempts/calls and configured runtime; it does not pretend role/date hints establish truth. Chunk ranges are internal to that exact consent; newly discovered files or changed content/labels/root generation require a new preview and consent before affected transmission. Revalidate full hash, canonical path and privacy before each chunk read and again at guarded publication; a mid-run change blocks outstanding work and makes old evidence stale. Retain unaffected completed sources; for a changed source, invalidate its old chunk coverage, draft contributions and dependent context as needed, do not mix versions, and show what is retained. Any invalidation must preserve human edits and existing accepted records/history as stale or needing review, never silently delete them. Reconsent explicitly covers the new outstanding source version, preserves unaffected consent lineage and never implicitly admits new files.

Each run gets a fresh immutable capability for exactly one chunk (including its explicit overlap), no general file-reading tool; explicitly allowlisted eligible prior context is the only additional passage access. Core/store reads and validates full local source but returns only the approved projection; enforce permitted byte ranges during candidate validation, including source endpoints and all draft/accepted context citations. Existing `SourceRef` already represents exact original-document byte ranges, full-document hash, passage hash, excerpt and optional heading: retain it for durable evidence; no synthetic chunk document or relative-offset citation. Host returns absolute original offsets with exact raw excerpt and SHA-256; any newly sourced model subrange must lie within the transmitted range or an explicitly allowlisted context passage, be on UTF-8 boundaries and match bytes/hash. `locator_valid` currently checks nearest preceding line beginning `#`, not a Markdown heading hierarchy: emit its actual matching heading or null, including heading-at-chunk-start and fenced `#` edge cases; do not invent heading paths. Validate all citations against the unchanged whole original. Protect TOCTOU at read and stage; malformed/out-of-range/forged headings or hashes fail closed. Fresh source retrieval must stay within the current authorized range. Existing eligible completed-draft and accepted context may explicitly supply prior consented passages under current privacy and provenance policy; those exact allowlisted context passages may also support citations. Context is not a general permission to read the parent source, and source-ID membership alone is insufficient.

No public-context identity oracle: context retrieval must not disclose a topic, human correction, hidden name, source ID/path, heading, excerpt or inferred identity derived from an unselected/private document. Consent to the selected whole file and its frozen chunk plan authorizes its canonical source ID and path metadata; retain existing `SourceRef` IDs and paths and original offsets. Overlap is disclosed in the plan and is drawn only from the same consented source. Associated eligible prior context must pass existing sensitivity, provenance and correction filters; suppress private/superseded human text and unselected sibling evidence or metadata. Generic date/source-type hints are retrieval hints only and cannot resolve identity, rank truth or create evidence. Scope delivery and source-bound assertions must test metadata as well as body.

## Accounting, budgets and lifecycle

Extend core-owned manifest/capability/checkpoint contract with source-version/chunk identities and coverage, while keeping source-level selected/processed/failed/outstanding reporting. Commit each successful chunk's buffered candidates, ID mapping and coverage atomically through the existing `CommitPermit` fence; mark a file processed only when all its primary chunks committed for the same hash. A failure, empty response without actual scope delivery, cancellation, exhausted attempt budget or restart mid-attempt leaves that chunk outstanding/failed; prior committed chunks and edits survive, no partial candidates escape. Retry only outstanding chunks within the consented finite attempts and total batches; explicit re-preview/reconsent if changed budgets are needed. Resume skips completed chunk IDs. Coverage UI shows files and chunks, gaps and exclusions, never claims full-folder coverage. The existing 64-candidate cap and existing attempt/failure handling remain in force; coverage represents successful required delivery and staging, not an evaluation of semantic recall.

Keep the current 64 KiB aggregate raw batch budget and 512 KiB frame, 256 KiB host response, 64 runtime candidates, and 2 MiB output caps. Account actual JSON serialization including duplicate excerpt/content, schema, escaped text and both SDK/direct envelopes; raw source bytes are not wire bytes. Before freezing consent, preflight the mandatory source projection plus eligible accepted/correction context and schema against the actual serialized envelopes; shrink ranges and rebuild the exact manifest before consent where needed. Recheck at delivery because context may change; existing packer trims only optional draft context. Large accepted context alone can exceed the bound even with a tiny chunk. Do not trim corrections, suppress privacy filters, or retry forever: fail before transmission with an actionable context/budget error and permit a narrower approved selection or a later separately designed context change; this slice does not require one. Optional draft records remain whole and dependency-consistent, with explicit partial notice; omitted context is not negative evidence. Verify actual worst-case envelopes with synthetic escape-heavy, multibyte and large mandatory accepted/draft fixtures. Even 16 KiB is not a guarantee when mandatory context is large; preflight and bounded failure remain required.

Overlap never counts twice as coverage or independent corroboration. Canonical evidence identity includes source version and absolute byte range; merge overlapping/identical citations from the same document as one underlying source occurrence while preserving distinct supporting passages and source lineage. Different copies are not independent confirmation. Reuse existing ID mapping and precise human corrections across chunks; repeated facts remain one fact when supported by the same evidence, but ambiguous same-name people, conflicting assertions, changed values and distinct endpoints remain issues, not automatic merges. Deduplication cannot rely only on hashes of exact excerpts (overlapping ranges may differ). Re-runs and reconsent must not duplicate topics/claims or revive suppressed assertions; test negative cases to avoid overmerging.

## Alternatives and decisions requested

Raising 64 KiB alone still fails for larger notes, duplicates content on wire and retains full-file disclosure; disabling validators is unacceptable. Hard truncation loses coverage. Sending whole documents per chunk defeats isolation. A separate vector store or knowledge-store rewrite is unnecessary. The above smallest coherent slice supports one complete large file within the existing 2 MiB source ceiling and all lifecycle/security paths, not just happy-path splitting; ordinary files can retain their current path while shared contracts remain compatible. The remaining product decision is whether to approve chunked analysis and its disclosed coverage/consent experience. Engineering defaults and their measurement limits are documented in the discovery report; implementation must verify them with RED and actual envelope tests. Do not treat this proposal as authorization.
