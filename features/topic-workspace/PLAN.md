## User journey and scope

Choose or create a root in desktop, including actionable empty/missing-root state. Select explicit Markdown files, folder or date range, preview the resolved file list and exclusions, and explicitly run analysis. Only selected eligible bytes may be transmitted. Review model-proposed people, projects, ongoing threads, claims and extensible typed connections, with citations and uncertainty; approve, edit or reject each dependency-consistent set. Browse accepted current knowledge, citations, unresolved identities and history. In topic chat, a model proposes a correction; user approval adds a superseding claim and scoped rule, which influences later analysis without reviving the false assertion. The model can never approve, apply or write notes. Manual proposal capture is a fallback, not a substitute for discovery.

No task backlog/daily migration, embeddings, automatic all-vault import, generated legacy pages, gateways, full 1:1 preparation, Claude backend or graph visualization. The UI must make unavailable Codex actionable and preserve manual capture and existing browsing. Date range uses indexed document dates, inclusive; undated documents are excluded and shown as such. Folder resolution excludes `topics/`, symlinks escaping root, non-Markdown and local-only sources; empty selection is actionable. Reconfirm when selection or source bytes change before transmission.

## Data, safety and recovery

The authoritative v1 records are specified in [CONTRACT.md](CONTRACT.md). IDs are stable, source paths are hints with content and passage hashes; a changed or missing source renders evidence stale, never silently reanchors it. Ambiguous names remain unresolved candidates; a reviewed explicit choice creates identity. Record uncertainty rather than implying attendance means understanding. Duplicate input/proposal fingerprints are visible and do not silently duplicate accepted assertions. New source analysis does not override a correction rule or current accepted revision automatically.

All app writes snapshot old bytes (including an explicit absent marker for creations) under Application Support before change. An operation journal records intended files, expected hashes and dependencies, staged bytes, progress and commit status. Validate dependencies and all expected hashes before starting; use cooperative process lock, same-directory temporary files, flush and rename each file. Publish a transaction commit marker last; projections ignore incomplete operations. On restart finish safely if preconditions still match, otherwise preserve staged/current/old versions and show conflict for resolution. No cross-file atomic rename is claimed. Existing files and original transcripts are never rewritten by analysis. Hash check plus rename cannot prevent all lost edits by an uncooperative editor in the intervening race; preserve snapshots, detect observable conflicts, and surface this limitation. Undo is a new journalled operation using expected hashes, with dependency checks; it does not erase history. Deleting the derived DB and rebuilding from Markdown plus committed operation metadata reconstructs accepted current and historical knowledge. Durable commit metadata must be under `topics/`, not solely Application Support; snapshots remain in Application Support.

Local-only labels apply to sources and topics; if any selected source is local-only it is excluded at the application-owned tool boundary and cannot enter a prompt, tool result or model-visible log. Unlabelled Markdown is unknown: explicit per-run confirmation permits only the listed unknown files for that run; it never overrides local-only. Labels are durable per-source records. A local-only source taints derived topics and citations local-only until explicitly reviewed; topic labels also deny cloud retrieval. Accepted local-only knowledge must not leak through search, topic reads, proposal evidence, errors or chat context. Model text and notes are untrusted, tool responses are bounded to the confirmed scope, no arbitrary file access. Runtime startup must fail closed if non-Topics tools cannot be excluded; never send real notes until negative isolation tests pass. No config, credentials or real notes are inspected in this planning task.
