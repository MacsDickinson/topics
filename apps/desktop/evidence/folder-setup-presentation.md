# Folder setup desktop evidence

Browser tests use the synthetic IPC fixture, not the native service or a model. They establish presentation behavior only; they do not establish persistence, privacy enforcement, job coverage, restart, guarded publication, or 100-document acceptance. Those remain dependent on real-service/native evidence and the service-owned mapping in `features/folder-setup/scenario-evidence.md`.

| Approved scenario | Desktop evidence |
| --- | --- |
| Connecting a new folder starts local setup without transmission | `connecting a new folder opens local inventory before analysis` checks no legacy model start; real local-only behavior remains service-owned. |
| Empty and returning folders have useful entry points | existing `create a fresh root` checks empty entry; returning root is browser-tested and restart is native-tested; pause/resume remains service-owned. |
| One consent covers an exact unchanged job manifest | `setup offers tree selection` and `setupJob` check visible exclusions, explicit consent and one create call; the cited-claim native run exercises 100 selected documents and five scoped calls; independent privacy/containment evidence remains service-owned. |
| Changed inputs require renewed consent | selection edit and renewed manifest authorization are browser-tested; changed-byte capability enforcement remains service-owned. |
| Batches build one sourced graph; ambiguous identities and historic disagreement | service evidence required; browser graph fixture only shows server-supplied items and an inferred issue. |
| A topic map is usable as a graph and as a list | `topic map offers graph and list navigation` checks toggling, topic selection, and disclosed source; native keyboard/edge evidence remains outstanding. |
| Save the eligible starting map; saving a topic group; visible dependencies | `draft map exposes one exact starting-map receipt` checks receipt presentation; whole-map and dependency-expanded topic-group saves are native-tested; independent partial-save semantics remain service-owned. |

`folder-setup-presentation-green.txt` records the browser run; light, dark, narrow, graph and corrected-topic images use synthetic fixture content. The original workspace tests were adjusted only for the approved empty setup screen and collapsed evidence; root-race assertions remain in place. The graph and correction screenshots do not substitute for real-service acceptance.

A parallel 32-test run had 31 passes and one timeout in the existing `review F4 refresh of the same topic preserves chat draft and consent` test while a button detached. The same test passed immediately in isolation; the final recorded run uses one worker and an isolated, injectable port. This timing failure remains a review item rather than proof that the underlying race is resolved.

The isolated native workspace run against core checkpoint `4815346` exercised actual Tauri IPC for an empty root, manual topic, source privacy and a raw user statement. The first run without the statement passed. After adding the statement, the prior undo-success assertion failed because the statement depends on the topic; the real service surfaced “Undo dependent operations first”. The revised native scenario expects the dependency conflict and retained topic. This does not cover the 100-note job, contextual correction or restart.

The revised real-service native workspace smoke passed with the statement dependency assertion, including two isolated invalid-app-data startup checks. It uses synthetic temporary notes, app data and a missing Codex executable; no provider was called. The direct statement service returned the same persisted text and ID on readback. `folder-setup-native-context-failure.txt` and `folder-setup-native-dependency-failure.txt` preserve the earlier failed undo expectation; the conflict was caused by the newly created dependent statement, not an operation-list timing issue.

The first isolated 100-note graph-only native attempt lost the Tauri bridge while another frontend build overlapped bundling and was stopped; the log is retained. A serial second attempt reached the real coordinator: its checkpoint reported 100 selected and processed, zero failed/outstanding, five model calls and one authorization, with the app-owned `topics` folder excluded. The status was correctly `finished_with_gaps` and `complete: false` because of that exclusion; the initial native assertion incorrectly expected full folder coverage and the run was stopped before saving. The test now checks the honest status; save and restart evidence are pending the rerun.

The graph-only native rerun (`folder-setup-native-100-green.txt`, using the previously built isolated test binary) passed: 100 synthetic notes, five bounded scripted calls, one transmission authorization, one explicit map save, and a fresh-process restart after deleting the disposable index. The app-owned folder exclusion is visible and coverage is correctly marked with gaps. This fixture emits topics and a cited relationship but no claim; correction, its provenance after restart, reconsent and final end-to-end acceptance remain untested by this run. An earlier green run had test titles that mistakenly mentioned correction despite skipping it; the final rerun uses accurate graph-only titles and additionally checks saved dispositions.

The additive core/job checkpoints and cited-claim renderer are now in use. `folder-setup-native-claim-final.txt` passed an isolated 100-note whole-map save, correction and supplemental-context restart; `folder-setup-native-group-final.txt` independently passed the same journey using a topic-group receipt. In the latter, the selected group plus its service-added endpoint saved every eligible fixture item in one decision; the test checked five runtime calls, one authorization, one confirmed revision, exact context readback and restart after index deletion. Both used synthetic notes and a local scripted app-server, not a provider. The first cited-claim run failed on a malformed WebDriver selector and is preserved; a browser regression run was also interrupted by source hot reload and is preserved separately. The job reports the app-owned exclusion as `finished_with_gaps`; these results do not claim full-folder coverage or independent integration review.

After the group native run, the reconsent view gained a list of removed paths and a retry for a ready job, and the topic-diff view was made resilient when prior understanding cannot be loaded. Those follow-up presentation changes were checked by the focused browser suite, not by another native rebuild. The final 38-test regression run predates the last focused-only changes; the final focused run has 14 passing tests. A 37-test browser attempt was interrupted when a source file changed during Vite hot reload; its failure log is retained and the serial rerun passed.
