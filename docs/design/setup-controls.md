# Folder setup controls

Folder setup adapts the free BoardUI Select and single DatePicker from commit `ec5c5eb3e29c2441be63b9422cd54f411ef23466` of https://github.com/BoardUI/boardui (MIT; copyright and license are in `apps/desktop/src/boardui/LICENSE`). The original source snapshots are retained alongside the adaptations. The React Aria Select/listbox/popover and Calendar/dialog/popover structures and pending Apply/Cancel selection are adapted to Topics semantic tokens and system fonts; the date chip uses strict ISO dates and Clear, and the controls do not use Tailwind preflight, animations, remote resources, Pro assets, or JavaScript Date conversion. Dependencies `react-aria-components` 1.17.0 and `@internationalized/date` 3.12.1 are pinned.

Each independent date bound can be cleared; bounds are inclusive and undated documents are excluded when either is active. A reversed range blocks review with an explanation. Oversized eligible notes appear in Needs attention with a direct exclusion action; informational exclusions are grouped by the actual backend reason and their paths remain available in disclosures. The exact manifest and explicit consent remain authoritative.

Example: select a date in the calendar or enter `2026-11-01` in its ISO date chip, then Apply. Cancel preserves the previous bound. Selecting a folder role changes the canonical role and invalidates the prior preview and consent.

## Verification and limits

The synthetic browser regression was red on the base: with a 28-byte dated note and two selected 167 KiB notes (one outside the range and one undated), Review manifest stayed disabled after choosing `2026-01-01`. It is green with the date-aware guard. The browser suite passed 118 tests on Node 24.22.2 with an isolated absolute app-data path and port 15152; it exercises direct removal from the request, invalid/reversed dates, role and ISO wire values, consent invalidation, keyboard cancel/focus return, and no implicit job creation. Browser transport fixtures do not prove filesystem byte preservation.

A fresh native-test build and the synthetic native setup, restart and reconsent suites passed using a temporary notes root and app data; the existing native setup suite verifies synthetic source hashes and local-only exclusion. It does not specifically exercise the new oversized/date-filter flow natively or validate a screen reader. Rust emitted a nonfatal `rust-objcopy` missing `libLLVM.dylib` warning while building the scripted fixture. Light, dark and narrow synthetic browser captures are in `apps/desktop/evidence/setup-controls/`. Independent review is still required, including examination of the source adaptation, date/calendar interaction and native oversized case. Eligible large notes remain unsupported and require explicit exclusion to continue.
