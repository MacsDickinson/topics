# Folder setup controls

Folder setup vendors the free MIT BoardUI sources from commit `ec5c5eb3e29c2441be63b9422cd54f411ef23466` of https://github.com/BoardUI/boardui; the copyright and license are in `apps/desktop/src/boardui/LICENSE`, and the original Select, single DatePicker and shared date-picker sources are retained alongside the running adaptations. The pinned dependencies are `react-aria-components` 1.17.0 and `@internationalized/date` 3.12.1.

`select.tsx` retains BoardUI's `Select` and `SelectItem`, React Aria trigger, value, nonmodal popover, listbox, controlled open state, outside-press dismissal and trigger-toggle guard; its visual classes use Topics semantic tokens. `date-picker.tsx` retains the upstream standalone trigger, nonmodal popover, Dialog, Calendar, open-key remount, controlled/uncontrolled values, pending selection and Cancel/Apply flow; `date-shared.tsx` retains `MonthPanel`, `DayCell`, editable `DateChipInput` and the original navigation SVG paths, while the calendar trigger uses a local SVG. The upstream outside-press and trigger-toggle utility is included locally. `controls.tsx` only adapts canonical role and independent optional date-bound values to these components.

Adaptations replace Tailwind classes and BoardUI colors with scoped Topics token CSS, remove the website localization wrapper and animation dependency, retain system fonts and offline operation, and use an English month label without converting civil dates through JavaScript timestamps. The date chip accepts and validates exact `YYYY-MM-DD` instead of the upstream day-first format, is visible before a day is chosen, and adds Clear and invalid-draft feedback; the picker has a bound-specific accessible label and restores trigger focus after explicit actions. Two single-date pickers preserve independent inclusive bounds, and undated documents are excluded when either bound is active. A reversed range blocks review; eligible oversized notes appear in Needs attention with an explicit exclusion action, and informational exclusions are grouped by backend reason with expandable paths.

Example: enter `2026-11-01` in the date chip, then Apply; Cancel preserves the previous bound, while Clear removes it. Changing a date or folder role invalidates the prior preview and consent; the exact backend manifest remains authoritative.

## Verification and limits

The base oversized regression was red: with a 28-byte dated note and selected 167 KiB old and undated notes, Review manifest stayed disabled after choosing `2026-01-01`. The component correction was also red against commit `9d3a48e`: the screen lacked the BoardUI month panel and editable date chip; the focused test now exercises both. See the worker handoff for final browser/build and native results. The source adaptations need independent review; supported notes remain subject to the existing 64 KiB cap, and eligible larger notes require explicit exclusion.

The browser suite passed 124 tests on Node 24.22.2 with `TOPICS_APP_DATA_DIR=/tmp/topics-boardui-final-browser` and port 15158; `npm run build` passed. Three synthetic captures show the restored picker in light, dark and narrow layouts.

The targeted native command `CARGO_TARGET_DIR=/Users/macs/orca/workspaces/topics/topics-m1-desktop/target node scripts/native-setup-oversize.mjs` passed with temporary notes and app data: it selected an ISO date, confirmed old and undated 167 KiB notes did not block, explicitly excluded an eligible 167 KiB note, reviewed the remaining small note, and checked all synthetic file hashes, the local-only inventory exclusion and absence of a job. No provider was used.

Initial WebDriver runs failed before date entry. A bounded event trace showed that the embedded driver's element click emitted a synthetic click followed by a window scroll; pinned React Aria's `useCloseOnScroll` then called `onOpenChange(false)` before the dialog received focus, while BoardUI's outside-press handler did not fire. The same native screen kept the popover open when its actual trigger was activated with DOM `click()` without the driver-generated scroll, after which the test used WebDriver to enter and apply the date; the source retains upstream dismissal behavior. The driver's `browser.keys(["Enter"])` delivered keydown without a button click in this environment, so this result does not establish real hardware-pointer or native keyboard acceptance; those interaction paths still need independent native verification. The synthetic app and WebDriver processes were closed and the GUI slot and target released.
